# Classroom Control

Система удалённого управления компьютерным классом через SSH — аналог
NetSupport School / Veyon, реализуемый на C с использованием libssh.

Подробное описание архитектуры см. в [`docs/architect.md`](docs/architect.md).

## Описание проекта

Один главный сервер (компьютер преподавателя) управляет несколькими клиентами
(компьютеры учеников) через SSH:

- отправка и выполнение произвольных команд терминала на клиентах;
- получение скриншотов экрана клиентов (в перспективе — живой стрим экрана);
- масштабирование на класс из 20–30 машин.

SSH встраивается напрямую через `libssh` (а не через вызов внешнего процесса
`ssh`), чтобы держать одно постоянное соединение (session) на клиента и
открывать внутри него несколько логических каналов (channels) — для команд,
для скриншотов, в будущем для видео.

Текущий этап разработки — транспортный слой: подключение к одному клиенту,
аутентификация по ключу, выполнение команды через exec channel.

## Зависимости

- `libssh` (аутентификация/транспорт по SSH)
- `gcc`, `make`, `pkg-config`

Установка на Arch Linux:

```bash
sudo pacman -S libssh gcc pkgconf make
```

## Сборка через gcc

Собрать debug-версию (с отладочными символами):

```bash
mkdir -p build/debug
gcc -g -Wall -Wextra src/main.c -o build/debug/classroom_control $(pkg-config --cflags --libs libssh)
```

Собрать release-версию (с оптимизацией, без отладочных символов):

```bash
mkdir -p build/release
gcc -O2 -Wall -Wextra src/main.c -o build/release/classroom_control $(pkg-config --cflags --libs libssh)
```

## Запуск

```bash
./build/debug/classroom_control
```

Перед запуском убедитесь, что:

- на клиенте (`192.168.100.149` в текущем коде) запущен `sshd`;
- публичный ключ проекта добавлен в `~/.ssh/authorized_keys` пользователя
  на клиенте;
- приватный ключ проекта существует локально и путь к нему совпадает с тем,
  что указан в `SSH_OPTIONS_IDENTITY` в `src/main.c`.

## Настройка SSH-ключей проекта

Аутентификация — только по ключам, отдельная пара под проект (не
переиспользовать личные ключи администратора):

```bash
ssh-keygen -t ed25519 -f ~/.ssh/classroom_agent -N ""
```

- Ключ создаётся **без passphrase** — агент должен подключаться
  автоматически без участия человека.
- Обязательные права доступа:
  ```bash
  chmod 700 ~/.ssh
  chmod 600 ~/.ssh/classroom_agent
  ```
- Публичный ключ (`classroom_agent.pub`) копируется на каждый клиент в
  `~/.ssh/authorized_keys` соответствующего пользователя.

## Известные грабли (libssh)

- `SSH_OPTIONS_IDENTITY` должен быть установлен **строго до** `ssh_connect()`,
  иначе аутентификация по ключу молча откатится на дефолтный путь
  (`~/.ssh/id_ed25519`) и провалится.
- `ssh_options_set` для `SSH_OPTIONS_PORT` принимает указатель, а не `int`
  напрямую:
  ```c
  ssh_options_set(session, SSH_OPTIONS_PORT, &(int){22});
  ```
- Права на приватный ключ обязаны быть `600`, на `~/.ssh` — `700`, иначе
  SSH молча откажется его использовать.

Полный список см. в разделе 11 [`docs/architect.md`](docs/architect.md).

## Безопасность

- Аутентификация только по ключам, отдельный ограниченный пользователь на
  клиенте (без sudo).
- В проде обязательна проверка `known_hosts`
  (`SSH_OPTIONS_STRICTHOSTKEYCHECK` включён) — отключение допустимо только
  на этапе разработки.
- Логирование всех выполненных на клиентах команд.
